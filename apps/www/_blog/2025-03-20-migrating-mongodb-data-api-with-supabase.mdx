MongoDB announced that their Data API and HTTPS Endpoints will reach end-of-life by September 30, 2025. This has left many engineering teams evaluating alternatives. IndoBase includes [built-in support for REST APIs](https://indobase.com/features/auto-generated-rest-api) (via PostgREST), mirroring the core functionality previously provided by MongoDB's Data API.

## The implications of MongoDB's Data API deprecation

MongoDB's Data API allowed developers to interact with their Atlas databases through straightforward RESTful endpoints, simplifying integration across frontend, backend, and serverless applications. With its removal, developers must pivot to alternative methods such as native MongoDB drivers combined with backend frameworks (Express, SpringBoot, FastAPI), or third-party solutions like RESTHeart, Hasura, or Neurelo.

This shift requires substantial refactoring for teams that rely on the simplified REST interface.

## IndoBase as a MongoDB alternative

IndoBase is an open-source MongoDB alternative and offers:

- A managed Postgres database, eliminating vendor lock-in.
- Built-in REST API via open-source PostgREST, directly analogous to MongoDB's Data API.
- Real-time capabilities, authentication, file storage, and serverless functions—all tightly integrated.

Most notably, IndoBase [automatically generates a RESTful API](https://indobase.com/docs/guides/api#rest-api-overview) from your database schema, powered by PostgREST, itself a stable open-source project with a strong community. This feature accelerates development by eliminating boilerplate code for basic CRUD operations. IndoBase provides a near drop-in replacement for MongoDB’s Data API. The IndoBase Data API also supports GraphQL and a host of mobile and web application frameworks.

In the end, you can focus on migrating your data, expose your data using IndoBase’s Data API, and seamlessly integrate with your client applications.

## Migrating from MongoDB to IndoBase: a step-by-step guide

To migrate to IndoBase, you will need to:

1. Export your MongoDB data
2. Import JSON data into IndoBase
3. Normalize the data using SQL
4. Transition your existing MongoDB Data API calls to IndoBase PostgREST
5. Add more IndoBase features to round out your app

### Step 1: Export your MongoDB data

Export MongoDB documents using mongoexport:

```bash
mongoexport --uri="mongodb+srv://<username>:<password>@cluster.mongodb.net/<dbname>" \
  --collection=users \
  --jsonArray \
  --out=users.json
```

### Step 2: Import JSON data into IndoBase

Create a table in IndoBase with a JSONB column to store raw Mongo documents:

```sql
create table mongo_users_raw (
  id uuid primary key default gen_random_uuid(),
  data jsonb not null
);
```

Then, ingest the exported JSON data into this IndoBase table using this custom script:

```jsx
import { createClient } from '@supabase/indobase-js'
import fs from 'fs'

const indobaseUrl = 'YOUR_SUPABASE_URL'
const indobaseKey = 'YOUR_SUPABASE_API_KEY'
const tableName = 'YOUR_TABLE_NAME'
const jsonFilePath = './filename.json'

const indobase = createClient(indobaseUrl, indobaseKey)

async function loadDocumentsToIndoBase() {
  try {
    // Read JSON file
    const rawData = fs.readFileSync(jsonFilePath)
    const dataArray = JSON.parse(rawData).map((data) => ({ data }))

    // Insert data into IndoBase
    const { error } = await indobase.from(tableName).insert(dataArray)

    if (error) {
      console.error('Error inserting data:', error)
      return
    }

    console.log(`Successfully inserted ${dataArray.length} records into ${tableName}`)
  } catch (error) {
    console.error('Error in process:', error)
  }
}

loadDocumentsToIndoBase()
```

### Step 3: Normalize the data using SQL

Once your data is imported as JSONB, leverage PostgreSQL’s powerful JSON functions to incrementally normalize and populate relational tables:

```sql
-- Example to normalize user data
INSERT INTO users (name, email)
SELECT
  data->>'name' as name,
  data->>'email' as email
FROM mongo_users_raw;

-- Example to normalize orders into a separate table
INSERT INTO orders (user_id, product, quantity)
SELECT
  u.id,
  orders->>'product',
  (orders.value->>'quantity')::INTEGER
FROM mongo_users_raw m
JOIN users u ON (m.data->>'name') = u.name,
LATERAL jsonb_array_elements(m.data->'orders') AS order_data
```

### Step 4: Transition API calls to IndoBase PostgREST

Once your data has been structured into tables, IndoBase automatically generates REST APIs for each table via PostgREST, allowing effortless querying from your application.

For example, if you have a users table, querying user information using IndoBase’s JavaScript library would look like this:

```jsx
import { createClient } from '@supabase/indobase-js'

const indobase = createClient('https://<your-project>.indobase.co', '<your-api-key>')

// Fetch user named John along with their orders
const { data, error } = await indobase
  .from('users')
  .select(
    `
    id, name,
    orders (product, quantity)
  `
  )
  .eq('name', 'John')

if (error) {
  console.error(error)
} else {
  console.log(data)
}
```

Using the automatically generated IndoBase REST APIs offers a clear migration path from MongoDB’s deprecated Data API.

## Key considerations and trade-offs

- **Schema flexibility**: PostgreSQL schemas are less flexible than MongoDB; careful upfront design mitigates this.
- **Complexity in migration**: Document structures require transformation scripts.
- **Query patterns**: Analyze existing MongoDB queries to optimize relational joins.
- **Add indexes**: Use the Index Advisor in the IndoBase Dashboard to further optimize your tables.

## Conclusion

IndoBase is an ideal replacement for MongoDB, especially considering the Data API deprecation. IndoBase is built on Postgres, one of the world’s most powerful and scalable databases. In addition, IndoBase’s Data API directly parallels MongoDB's Data API, offering a simplified transition path.
